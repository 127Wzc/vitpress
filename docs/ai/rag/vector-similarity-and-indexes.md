# 向量相似度与索引算法对比

**相似度是“尺子”，决定怎样比较向量；索引是“导航”，决定怎样找到候选。** 两者配合使用，例如 Cosine + HNSW。

## 相似度：尺子家族

```text
相似度度量 / 尺子家族 (Distance & Similarity Metrics)
│
├── 1. 夹角方向派（看方向，忽略向量长度）
│   └── 余弦相似度 (Cosine) ──【量角器】
│       └── 比较夹角，越大越相似；常用于文本语义检索
│
├── 2. 坐标距离派（看各维度相差多少）
│   ├── 欧氏距离 (Euclidean / L2) ──【直尺】
│   │   └── 两点之间的直线距离，越小越接近
│   └── 曼哈顿距离 (Manhattan / L1) ──【走街区的出租车】
│       └── 各维度差值的绝对值之和，越小越接近
│
├── 3. 方向与长度派（两者共同参与打分）
│   └── 点积 / 内积 (Dot Product / IP) ──【综合天平】
│       ├── 未归一化：方向和长度共同影响分数，越大越相似
│       └── 查询与文档都归一化：点积等于余弦相似度
│
└── 4. 集合与二进制派（看重叠，或找不同）
    ├── 汉明距离 (Hamming) ──【玩找茬】
    │   └── 等长二进制串中不同位的数量，越小越接近
    └── 杰卡德相似度 (Jaccard) ──【交集占比】
        └── 集合交集 ÷ 并集，越大越相似；适合出现项重合比较
```

记住三个细节：

- **度量先遵循模型约定**，文本与图像都可能使用 Cosine、IP 或 L2。
- 余弦忽略的是向量长度，不保证同主题的长短文本一定满分；点积里的长度也不天然代表热度。
- 查询和文档向量都做 L2 归一化后，Cosine、IP、L2 的**精确排序等价**，但分值、阈值不同。余弦距离通常为 `1 - Cosine`，越小越好。

归一化关系见 [Faiss 度量说明](https://github.com/facebookresearch/faiss/wiki/MetricType-and-distances)。

## 向量检索：KNN 与 ANN 家族

**KNN（K-Nearest Neighbors）是找最近 K 个邻居的任务**，可以精确求解，也可以近似求解；ANN（Approximate Nearest Neighbor）是允许少量漏检、换取速度或存储收益的方法家族。

```text
最近邻检索 / KNN（找最接近查询的 K 个向量）
│
├── 1. 精确 KNN（按指定度量，找出真正的 Top-K）
│   └── Flat / 暴力搜索 ──【挨家挨户敲门】
│       ├── 对全部原始向量计算距离，适合做评测基准
│       └── 数据量、维度增加，计算量随之增加
│
└── 2. ANN 近似最近邻（用一定召回损失换取效率）
    ├── 图导航派
    │   └── HNSW ──【立体交通网 + 邻居带路】
    │       ├── 上层定位区域，底层沿邻近节点细找；图结构占空间
    │       └── ef_search 越大，通常召回越好、耗时越高
    │
    ├── 聚类分区派
    │   └── IVF ──【先找圈子，再进圈搜索】
    │       ├── 查询只探查部分倒排列表，可能漏掉其他簇的近邻
    │       ├── IVF-Flat：分区搜索 + 原始向量
    │       └── nprobe / probes 越大，通常召回越好、扫描越多
    │
    └── 量化压缩派
        └── PQ ──【用小编号代替长向量】
            ├── 分段编码，节省存储，但距离估计有误差
            └── IVF-PQ：分区搜索 + PQ 编码，兼有两类误差
```

**Flat 只是精确 KNN 的一种实现；PQ 是可与搜索结构组合的压缩方法。** IVF-Flat 的簇内计算虽然精确，搜索部分簇时整体仍属 ANN；PQ 即使扫描全部编码，也可能因量化误差漏掉真实近邻。方法对照见 [Faiss 索引总览](https://github.com/facebookresearch/faiss/wiki/Faiss-indexes)。

## RAG 怎么选

先确定模型适用的度量，再按资源和延迟要求选择搜索方式：

| 情况 | 可以先验证的方案 |
| --- | --- |
| 个人知识库、低并发 | Flat，先测实际延迟 |
| 查询延迟要求较高、内存较充足 | HNSW |
| 接受聚类训练，希望减少扫描量 | IVF-Flat |
| 向量存储压力大 | IVF-PQ + 原始向量精排 |

没有统一的“过万就慢”或“召回率必达 98%”。用同一批查询比较精确结果、相关文档命中、P95 延迟和内存，再决定方案。

以 BGE 组合为例：

- **BAAI/bge-m3**：把问题和文档转成向量，dense 输出为 1024 维；还支持 sparse 和 multi-vector，托管接口是否提供需另行确认。见 [官方模型卡](https://huggingface.co/BAAI/bge-m3)。
- **BAAI/bge-reranker-v2-m3**：对召回的“问题 + 文档”重新打分，挑选上下文，再交给大模型生成回答。见 [官方模型卡](https://huggingface.co/BAAI/bge-reranker-v2-m3)。

实际落地操作参见 [pgvector 基础笔记](../../db/postgresql/postgresql-pgvector-info.md)。
